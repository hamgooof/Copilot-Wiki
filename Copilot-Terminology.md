# Copilot terminology without the headache

_Plain-English definitions for new and regular Copilot users - Last reviewed 12 August 2026_

You do not need to memorise a dictionary before using Copilot. Start with the fundamentals, then return to the extended terms when you encounter them.

[[_TOC_]]

## Fundamental terminology

### Text and working space

Use one whiteboard analogy for this group:

| Term | Plain-English meaning | Whiteboard analogy |
| --- | --- | --- |
| **Token** | A number representing a piece of text that a model processes | One numbered magnetic tile |
| **Context** | The information available to the model for its current call | The information currently available at the board |
| **Prompt** | The concrete input assembled for one model call | The incoming tiles placed on the board for this call |
| **Context window** | The maximum token capacity shared by input, generated output and supported reasoning | The fixed size of the whole board |

A prompt can contain role-labelled instructions and messages, tool descriptions, file content and earlier tool results. Context is the information the model can use; the prompt is how that information is packaged for a particular call.

### Who does what

Use one engine-and-vehicle analogy for this group:

| Term | Plain-English meaning | Analogy |
| --- | --- | --- |
| **Model** | A particular language model offered through Copilot. It generates output one token at a time by predicting the next token from the current context | The engine: models differ in power, speed, efficiency and suitability |
| **Agent harness** | The product layer around the model that assembles input, exposes tools, executes requests and manages the loop | The vehicle around the engine: controls, steering and connection to the environment |
| **Tool** | A callable ability such as searching, reading, editing or running a command | The hands and equipment used to perform work |
| **Agent** | A model working through a harness with context and tools | The complete working setup |

GitHub Copilot, Claude Code and Codex are examples of coding harnesses built around language models.

## Conversation and agent terms

| Term | Meaning used in this wiki |
| --- | --- |
| **Agent mode** | An IDE interaction in which Copilot can use tools and continue through several rounds |
| **Turn** | The exchange from one user message to Copilot's final answer |
| **Round** | One pass through the internal model-and-tools loop; one turn can contain many rounds |
| **Session** | One independent conversation with its own history |
| **Tool request** | Structured output asking the harness to execute a tool with particular arguments |
| **Tool result** | The output returned after the harness executes a tool |
| **Compaction** | Replacing some older conversation detail with a shorter summary to create context-window space |

[One prompt, many rounds](One-Prompt-Many-Rounds.md) shows these terms in a worked example.

## Customisation terms

| Term | Plain-English meaning |
| --- | --- |
| **Custom instructions** | Standing guidance automatically applied within a repository or path scope |
| **Skill** | A reusable playbook for performing one kind of task, optionally with scripts, examples and references |
| **Prompt file** | A saved job request that a person deliberately invokes |
| **Custom agent** | A reusable worker configuration with a role, instructions, tools and optional model choice |
| **Subagent** | A separate worker invoked to handle a delegated task and return a result |

The short distinction is:

- A **custom agent** defines the worker
- A **skill** defines a playbook the worker can use

One agent can use several skills, and the same skill can be reused by different agents. [Choose the right Copilot technology](Copilot-Technologies/Choose-the-right-technology.md) provides concrete examples.

## Tokens in more detail

A tokenizer belongs to a model provider or model family, not to Copilot as a whole. It splits text into pieces and maps those pieces to numeric token IDs.

Different models, including models in the same family, can tokenise identical text differently. That detail matters when investigating usage, but most users only need the four counts below:

| Count | Meaning |
| --- | --- |
| **Input tokens** | The assembled input processed for a model call |
| **Output tokens** | Text and tool requests generated by the model |
| **Cached input tokens** | A matching input prefix that the provider can reuse |
| **Reasoning tokens** | Internal working reported by supported reasoning models |

[Tokens and context windows](Tokens-and-Context-Windows.md) explains the whiteboard analogy, token IDs and context growth.

## Five distinctions worth remembering

### Model versus agent

The model is the engine. The agent is the working system around it: model, harness, context and tools.

### Prompt versus context

Context is the information available to the model. The assembled prompt packages that information for a particular call.

### Skill versus tool

A skill explains how to perform a workflow. A tool performs an operation. A testing skill might tell an agent when and how to use file, terminal and test tools.

### Custom agent versus skill

A custom agent changes who Copilot is configured to act as for the active worker or delegated task. A skill supplies a reusable method for one task.

### Instructions versus enforcement

Instructions influence model behaviour. Formatters, analysers, tests, permissions and repository controls enforce deterministic rules.
