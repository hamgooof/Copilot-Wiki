# Copilot terminology

| Page status | Intended audience | Last reviewed |
| --- | --- | --- |
| Draft glossary for internal review | Existing Copilot users new to agentic terminology | 8 August 2026 |

AI products sometimes use the same word differently. This glossary states how each term is used in this wiki and calls out important product-specific meanings.

## Core terms

| Term | Plain-English meaning |
| --- | --- |
| **Large language model (LLM)** | The model that reads an input and generates text, code or requests to use tools. |
| **Model** | A particular LLM offered through Copilot. Models differ in capability, speed, context size and cost. |
| **Prompt** | The complete input sent to the model. It is assembled from more than the text typed by the user. |
| **User message/request** | The instruction or question a person submits to Copilot. One request may cause several internal model calls. |
| **Response** | The visible answer or result returned after Copilot finishes processing a request. |
| **Token** | A unit used to measure model input and output. A token can be a word, part of a word or punctuation; it is not the same as a character or word. |
| **Context** | Everything the model can see for the current model call. |
| **Context window** | The maximum amount of context a model can process at once, measured in tokens. |
| **Input tokens** | Tokens sent to the model, including instructions, history, file content and tool results. |
| **Output tokens** | Tokens generated by the model. |
| **Cached tokens** | Reused or stored context handled through the model provider's prompt-caching mechanism. Pricing depends on the model and product. |
| **Thinking/reasoning tokens** | Tokens some reasoning models use internally. They may be invisible in the answer but still affect context or usage. |

## Conversation terms

| Term | Meaning used in this wiki |
| --- | --- |
| **Chat** | The interface used to exchange messages with Copilot. |
| **Session** | One independent conversation and its accumulated context. A new session starts with fresh conversation history. |
| **Conversation history** | Earlier messages, responses and relevant tool activity retained in the session context. |
| **User interaction** | One message submitted by a person and the work Copilot performs before control returns. |
| **Turn** | In the Copilot SDK agent-loop documentation, one LLM call and its consequences. One user interaction may contain several turns. |
| **Round** | Not used as a formal Copilot product term in this wiki. In experiments, a round means one complete repetition of a test scenario. |
| **Compaction** | Summarising older conversation history to free space in the context window. Some fine detail can be lost. |
| **Checkpoint** | An overloaded product term. In Copilot CLI it is a saved copy of a compaction summary. In VS Code, checkpoints are restore points used to roll back a session's file changes. |
| **Prompt cache** | A mechanism that lets a model provider reuse stable earlier input, potentially reducing cost and latency. |

## Agent terms

| Term | Plain-English meaning |
| --- | --- |
| **Tool** | A callable ability such as reading a file, editing code, running a command or querying an external service. |
| **Tool call** | A model's request for Copilot to execute a tool with particular arguments. |
| **Tool result** | The data returned by the tool. It becomes context for the next model decision. |
| **Agent** | The system that combines a model, context and tools to plan and perform work. |
| **Agent loop** | The repeated cycle of deciding, calling a tool, observing the result and deciding what to do next. |
| **Custom agent** | A reusable specialist definition with its own instructions, tool selection and optional model configuration. |
| **Subagent** | A separate agent invoked for delegated work, with its own context window on supporting surfaces. |
| **Orchestrator/parent agent** | The agent coordinating the overall task and delegating work. |
| **Child agent** | Another term for a subagent created by a parent. |
| **Handoff** | Passing a task or the next stage of work to another agent. |
| **Autonomy** | How much an agent may do without pausing for human approval. |

## Customization and extension terms

| Term | Plain-English meaning |
| --- | --- |
| **Custom instructions** | Guidance that is automatically applied in a defined scope, such as a repository or file path. |
| **`AGENTS.md`** | A file format for standing repository guidance used by supporting AI agents. Discovery rules vary by client. |
| **Skill** | A task-specific package containing `SKILL.md` and optional scripts or resources, loaded when relevant. |
| **Prompt file** | A reusable prompt that a person invokes for a particular interaction on supporting IDEs. |
| **MCP server** | A Model Context Protocol server that supplies tools or data sources to an AI application. |
| **Hook** | A configured command that runs at a specific lifecycle event, such as before a tool call or after an agent stops. |
| **Plugin** | An installable bundle that can package customizations such as agents, skills, hooks and MCP configuration. |
| **Copilot Memory** | A supported feature for storing and later retrieving repository facts or user preferences. It is separate from one chat's context. |
| **Copilot Space** | A curated collection of instructions and sources used to ground Copilot Chat around a topic or project. |

## Usage and cost terms

| Term | Plain-English meaning |
| --- | --- |
| **GitHub AI Credit** | GitHub's current usage-based billing unit. One credit corresponds to USD $0.01, but token prices differ by model. |
| **Usage-based billing** | Billing based on the model used and tokens consumed, converted into AI credits. |
| **Premium request** | The legacy request-based unit still applicable to certain existing annual individual plans. Do not mix it with AI-credit accounting. |
| **Rate limit** | A temporary restriction on request frequency or capacity. It is different from exhausting a credit allowance or budget. |
| **Budget/session limit** | A control used to cap or stop further AI-credit consumption. Exact availability depends on plan and surface. |

## Important distinctions

### User request versus turn

You might submit one request and see one final response, but the agent may have called the model multiple times internally:

```text
One user request
  Turn 1: model asks to search
  Turn 2: model asks to read two files
  Turn 3: model asks to edit a file
  Turn 4: model asks to run tests
  Turn 5: model produces the final response
```

This is why “one prompt” does not necessarily mean “one model call” or a fixed cost.

### Model versus agent

The **model** reasons and generates. The **agent** gives the model context and tools, executes requested actions and manages the loop. A custom agent can use different models without itself being a model.

### Context versus memory

Context is what the model can see now. Memory is information stored for possible use in later sessions. A repository file is a persistent source that can be retrieved; it is not automatically present in context.

### Skill versus tool

A skill normally supplies instructions, workflow and supporting resources. A tool performs an operation. A skill can instruct the agent to use tools.
