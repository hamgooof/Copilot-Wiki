# Tokens and context windows

| Page status | Intended audience | Last reviewed |
| --- | --- | --- |
| Draft foundation page | Existing Copilot users new to context management | 8 August 2026 |

The context window is Copilot's working space for one model call. Understanding what fills it is one of the most useful ways to improve both quality and efficiency.

## What is a token?

A token is a unit used by a language model to represent input and output. Tokens are often short words or fragments of longer words. They are not a reliable one-to-one match for words or characters.

You do not normally need to count tokens manually. The useful point is that every item sent to or generated by the model occupies tokens.

## What is context?

Context is everything the model can see while generating its next response. In a Copilot session this can include:

- Built-in system instructions.
- Descriptions of available tools.
- Personal, organisation, repository and path-specific instructions.
- A custom agent profile or invoked skill.
- Your current request.
- Earlier messages and responses.
- Selected or retrieved files and code.
- Terminal output, search results and other tool results.

The exact mix is assembled by the product and varies by Copilot surface.

## What is the context window?

The context window is the maximum number of tokens a model can process for one call. Different models have different limits.

Think of it as a workbench:

- Relevant material makes the task easier.
- Irrelevant material takes up space and distracts from the job.
- When the bench becomes full, something must be removed, summarised or moved elsewhere.

More context is therefore not automatically better. **Relevant context** is better.

## How context grows during agent work

Suppose an agent is investigating a failing test:

1. The initial instructions, user request and tool definitions enter the context.
2. A search tool returns matching files.
3. File-reading tools add code.
4. A test command adds terminal output.
5. The model calls another tool using everything accumulated so far.
6. Each later model call may include the growing history of earlier calls and results.

This is why an apparently short user request can result in substantial token usage.

## What happens when the window fills?

Copilot surfaces can compact conversation history by replacing older detail with a structured summary. This frees space but cannot guarantee preservation of every minor decision or exact command output.

Current Copilot CLI documentation describes automatic background compaction beginning at approximately 80% of capacity and waiting if usage reaches approximately 95% before compaction completes. VS Code's February 2026 release notes document automatic and manual context compaction, but do not give the same thresholds. These behaviours are product details and can change.

If exact information must survive, store it in a file rather than relying only on old chat history.

## Good and poor context

Poor request:

```text
Fix the authentication.
```

The agent must guess the intended component and may search widely.

Better request:

```text
Fix the expired-refresh-token handling in src/auth/refresh.ts.
Preserve the existing error response, add a regression test in the matching
test file, and run the auth unit-test command from package.json.
```

The second request provides scope, constraints and success criteria. It can reduce exploration while improving accuracy.

## Sources of avoidable context bloat

- Large instruction files containing rarely relevant workflows.
- Attaching whole folders when two files are sufficient.
- Reusing one chat for unrelated tasks.
- Allowing commands to return extremely large logs.
- Enabling many irrelevant tools or MCP servers.
- Repeatedly pasting documentation that could be retrieved when needed.
- Asking multiple agents to duplicate the same investigation.
- Continuing after Copilot has become stuck in a repeated approach.

## Practical context habits

### Start a fresh session for a new task

A session has its own history and context window. Starting a new one removes irrelevant history. This is not a failure; it is routine context hygiene.

### Reference the smallest useful scope

Name the component, file, symbol, issue or error. Let repository search retrieve related code instead of attaching everything.

### Make constraints durable

Put broad, stable rules in concise custom instructions. Put task state or decisions in a working document. Put occasional workflows in skills.

### Keep tool output controlled

Filter test output, search results and logs when practical. Ask for a summary first and retrieve the full result only when necessary.

### Compact between phases

After a large research or planning phase, compaction can create room for implementation. Review the resulting summary when the task contains critical detail.

### Delegate noisy independent work

Subagents can keep extensive exploration out of the main context, but the task and required output must be clearly specified.

## How to observe context

- VS Code provides a context-window control and automatic/manual compaction on supported agent sessions.
- Copilot CLI provides `/context` for context composition and `/usage` for session statistics.
- `/compact` can manually summarise history on supporting surfaces.
- VS Code's [Cache Explorer](https://code.visualstudio.com/docs/agents/agent-troubleshooting/cache-explorer) compares consecutive model requests to help diagnose prompt-cache misses. It is available from the Agent Debug Logs panel.

Use these measurements before making claims about what consumes context. An installed feature may have discovery metadata overhead even when its full instructions are not loaded.
